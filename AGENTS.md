# local-models hub

Write the maker's display name as **Haedo Labs™** in the app, plugin metadata, and documentation. Link the whole byline. Maker credits stay sapphire on paper (`#0f52ba`) and dark (`#3879e4`) when the dashboard or Mac accent changes.

A gateway on `localhost:1235` in front of LM Studio, shared by projects and coding sessions on the Mac: admission control across all clients, per-request attribution by project and session, model replicas kept loaded, crash reloads and pre-emptive recycling, read-only local agents, and one dashboard. The repo is also a Claude Code plugin and its own marketplace. The guide for clients is [GUIDE.md](GUIDE.md); the overview is [README.md](README.md).

## Layout
- `localmodels/gateway.py` — the gateway: attributes each request, acquires a slot, forwards to LM Studio, logs one line, holds and resends across a crash.
- `localmodels/supervisor.py`, `worker.py` — zero-downtime deploys: the supervisor (standard library only, nothing else from the package) holds the listening sockets and runs workers from immutable `releases/<digest>`; a new worker warms up and self-tests before it accepts, the old one drains with no deadline, and roles (instance manager, peer poller, memory sampler, link listener, and batch recovery) are flocks held by one serving worker.
- `localmodels/llmshare.py` — the sharing rules: slot locks, leases, the swap lock, the model listing, the readers of the shared state.
- `localmodels/models.py`, `crashes.py`, `recycle.py` — the instance manager: replicas kept loaded, an embedding family (`"kind": "embedding"`) kept loaded beside them, crashed instances reloaded, instances recycled before the crash threshold; `crashes.ENGINE_WORDS`, the one list of the engine's failure words.
- `localmodels/watchdog.py` — the stall watchdog: an instance still listed whose engine wrote nothing in LM Studio's log (a request answering 120 s with no engine line since it was sent, or 600 s of silence with requests in flight) is taken out of routing, its requests cut and resent by the gateway, and reloaded by a stall job (`recycle.py`).
- `localmodels/affinity.py` — prefix affinity: a digest of each request's opening (system prompt, first message) and the copy that last answered it, put first among the candidates so the engine's per-instance prompt cache serves the follow-up; in memory only.
- `localmodels/admission.py` — admission by context size: each request's estimated context and each instance's budget, using the memory sampler's timestamped `run/admission.json`. Host probes and token calibration run outside request admission.
- `localmodels/runs.py`, `maint.py` — run and phase progress with finish times, run plans (`/hub/runs`) and per-phase estimates in tokens per item; maintenance windows and the switched-off state (`localmodels off` / `on`, `off --peers`: requests sent to the peers only; a peer's, `localmodels peer off` / `on <name>`).
- `localmodels/peers.py` — other Macs' gateways as more replicas of a family: the shared token, a peer's report, the front's link (polls, backoff, free slots, model fingerprints), and the network checks. A peers-only front requests missing embedding families from the peer's instance manager and exposes matched embeddings in `/api/v0/models`.
- `localmodels/agent.py` — local agents: the tool loop, read-only file tools, JSON answers, retries.
- `localmodels/mcp_server.py` — the MCP tools and job entry points. File scope follows the Git checkout or session directory; worktrees share their main checkout's job namespace.
- `localmodels/batches.py` — durable batch submission, pinned inference, private SQLite outcomes by `custom_id`, and the serving worker's batch recovery role. `python3 tests/test_batches.py --acceptance` runs the two 10,000-item interruption tests against sandbox gateways.
- `localmodels/whois.py`, `sessions.py` — who is behind a connection; recent Claude Code and OpenCode sessions on the Mac.
- `localmodels/web.py`, `dash.html`, `dash.py` — the dashboard and the terminal dash.
- `localmodels/names.py`, `errors.py`, `demo.py`, `pictures.py`, `icon.py` — display names and screenshot mode; the error recorder; the synthetic workload of `localmodels demo`; the README's pictures (`localmodels pictures`, screenshot mode only); the icon (a chip: sapphire die, off-white pins) as PNG and SVG; `python3 -m localmodels.icon` writes `brand/` and `docs/icon.png`.
- `localmodels/cli.py`, `bin/localmodels` — the command.
- `app/` — the optional menu-bar app (Swift and AppKit, no packages): `Glance.swift` turns `/hub/snapshot` into the icon, menu, and notifications; `Menu.swift` keeps the open menu in place across polls; `ExtensionIO.swift` restricts redirects and drains extension commands' output. `app/tests/main.swift` runs with the sandbox suites when `swiftc` is present. `main.swift` is the app; `localmodels app install` builds and signs it ad hoc on this Mac.
- `localmodels/extensions.py` — the extension protocol (version 1, GUIDE.md *Extensions*): a manifest per extension in the state folder's `extensions/`, the menu it serves as JSON, and the closed set of actions the app may take for it (a page or a POST on its own origin, a verb its manifest lists); `localmodels ext [check]`; the dashboard's launcher (`/hub/extensions`, `POST /hub/extensions/run`). The hub never imports an extension and never starts one on its own (only a person's click runs a verb its manifest lists); its code and tests name none (a made-up one).
- `localmodels/deploy.py` — `install`'s paths: a fresh start, the one-time migration from a gateway before releases, a LaunchAgent change, a supervisor upgrade, a deploy; `tools/launchd_probe.py` checks launchd's side with a temporary agent.
- `tests/` — sandbox tests with a fake LM Studio (two gateways for peers; `test_handoff.py` deploys under load with a supervisor; `test_supervisor.py` plays launchd for every install path, the failure rules and the migration); each imports `tests/_sandbox.py` first, so its state folder, port and LM Studio are temporary; `tools/` — measurements.
- `docs/` — the README's pictures, made by `localmodels pictures` in screenshot mode (`localmodels present on`) during `localmodels demo`.

## Working on it
- After any change: `localmodels check` (it runs the sandbox tests against the installed gateway), then `localmodels install` (it hands off to a worker from a new release with nothing refused or cut; `localmodels` reports *stale code* until then). A new rule gets a sandbox test first.
- Standard library only, Python 3.9 or later. No dependencies.
- Never stop LM Studio's server. Never unload or reload a model another run is using (`localmodels swapcheck`). Never put a prompt, a completion or a file's contents in the hub's records.
- Precise technical terms in anything a person reads (the dashboard, CLI output, error messages, MCP tool text): its readers are engineers. Name things by what they are (gateway, instance, replica, slot, admission queue, lease, recycle), not by metaphor ("door", "keeper").
- The Haedo Labs™ palette is near-black `#111110`, off-white `#ece7df`, the grey `#8d867c`, the hairline `#262522`, and sapphire `#0f52ba` as the one color (light theme: the same on off-white paper); sapphire is the default of the dashboard's color setting, which can take the Mac's system accent (`/hub/accent`) or a color of one's own instead (`applyAccent` in dash.html redraws every step from it). Series and project colors are steps of sapphire (its OKLab hue, lighter or darker, neighbours apart); "other" is a neutral. Type is Libre Franklin, 400 and 500 only (served by the gateway, SIL OFL), small labels in tracked capitals; the name is drawn as outlines. Behind it, a faint circuit board in sapphire (`localmodels/pcb.svg`, one seamless tile). No red anywhere: states are told apart by words and position first, warning in the beige-grey `#bca496`, critical in the strongest ink; the terminal dash uses the same palette. Motion is slow and subtle and stops under reduced motion. Colors come from the theme tokens, never literals.
- Commit only this repo's files. Nothing personal, no other project's name, no narration in anything committed; local notes go in a `*.local.md` file beside this one, which git ignores; when it is here, its "Now" section says what is open on this machine.
- **Commit** means commit the intended changes and run `localmodels commit`: the local release gets the next `X.Y.Z` patch number and tag `vX.Y.Z`. Use `--version X.Y.Z` for an explicit version. Install the tagged checkout on this Mac.
- **Push** means `localmodels push` (`publish` is an alias): run the sandbox tests, `claude plugin validate`, and the privacy and secrets checks, then send the existing tagged commit and its tag to GitHub atomically. Only an explicit push or publish request authorizes this. Git's signing settings apply to commits and tags. `localmodels install` maintains the pre-push hook for plain Git pushes too. The repository runs nothing on GitHub (no Actions or install scripts).
- When a default, module, command or endpoint changes, update every document that states it (README, GUIDE, AGENTS.md, the CLI help): search them for the old value.
- Look at what ships before it ships: render the README with GitHub's stylesheet, open each generated image at full size, read CLI output as its reader would. After a release, load the repository page signed out, in both themes.
- Verify every load and unload against LM Studio's listing afterwards: an unload by identifier takes the oldest instance of that model key.
